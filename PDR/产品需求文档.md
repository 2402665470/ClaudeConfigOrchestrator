🚀 Claude Code 本地环境管理器 (L.E.M) - 终极技术规格说明书 (v3.0)
0. 核心定义与纠错 (必须严格遵守的事实)

    安装机制: 严禁使用 claude /plugin install。必须使用 文件系统旁加载 (Filesystem Sideloading)。

    路径解析: MCP 配置中的路径（如 ./script.py）不需要我们在 JSON 层面做绝对路径重写（这是之前的误解），Claude CLI 会自动基于配置文件位置解析相对路径。我们只负责合并 JSON 对象。

    冲突策略: 遇到同名文件 -> 必须弹窗让用户选择 [覆盖] 或 [跳过]。

1. 全局配置 (Global Configuration)

存储位置: AppData/config.json

editor_path	String (Path)	[关键] 外部编辑器路径 (如 Code.exe)。用于点击文件时调用。	之前对话确认的需求
git_path	String (Path)	Git 可执行文件路径。	用于执行 Clone 操作

3. 业务逻辑 A：市场解析器 (The Parser)

目标: 将用户输入的 URL 转化为上述标准结构。

流程:

    输入: 用户输入 wshobson/agents。

    克隆: git clone https://github.com/wshobson/agents.git {TempDir}。

    智能扫描 (Heuristics): 遍历 {TempDir}，执行以下搬运逻辑：

        发现 *.md 且看起来像角色定义 (或在 agents/ 目录下) -> 移动到 Library/{ID}/assets/agents/。

        发现 含有 SKILL.md 的文件夹 -> 整个文件夹移动到 Library/{ID}/assets/skills/。

        发现 claude_desktop_config.json 或 mcpServers 键 -> 提取该 JSON 对象 -> 保存为 Library/{ID}/assets/mcp.json。

        发现 脚本文件在 hooks/ 目录下 -> 移动到 Library/{ID}/assets/hooks/。

    生成: 创建 metadata.json。

    入库: 移动到 {library_path}。

4. 业务逻辑 B：智能注入器 (The Injector)

目标: 将 Library 内容应用到 Project。

输入: Plugin_ID, Target_Path, Conflict_Strategy (Overwrite/Skip)
步骤 1: 物理文件复制 (Copy)

    源: Library/{ID}/assets/agents/* -> 目标: Target/.claude/agents/

    源: Library/{ID}/assets/commands/* -> 目标: Target/.claude/commands/

    源: Library/{ID}/assets/hooks/* -> 目标: Target/.claude/hooks/ (注意: Linux下需 chmod +x)

    源: Library/{ID}/assets/skills/* -> 目标: Target/.claude/skills/ (递归复制整个文件夹)

        逻辑: 如果 Target/.claude/skills/pdf-reader 已存在，且策略为 Overwrite，则删除旧文件夹，写入新文件夹。

步骤 2: MCP 配置合并 (JSON Merge)

    源: Library/{ID}/assets/mcp.json

    目标: Target/claude_desktop_config.json (或 claude.json)。如果不存在则创建 { "mcpServers": {} }。

    操作: 使用 lodash.merge 或类似深度合并算法，将源的 mcpServers 合并入目标。不修改路径字符串。

步骤 3: System Prompt 注入 (XML Anchor)

    源: (可选) 插件内的 Prompt 片段。

    目标: Target/CLAUDE.md。

    操作:

        读取 CLAUDE.md。

        寻找 <rolePrompt>...</rolePrompt> 标签。

        若存在，替换标签内文本。

        若不存在，在文末追加。

5. 业务逻辑 C：项目与场景管理
5.1 项目切换逻辑 (CLAUDE.md Switching)

    事实: Claude CLI 启动时只读根目录 CLAUDE.md。

    机制:

        用户在项目下建立 profiles/ 文件夹（如 profiles/dev.md, profiles/test.md）。

        UI 下拉菜单列出 Dev, Test。

        用户选择 Test -> 工具执行 fs.copy('profiles/test.md', 'CLAUDE.md') (覆盖)。

5.2 场景 (Scenes) 逻辑

    定义: 场景 = 插件引用的集合 (JSON)。

    创建: "从项目快照"。

        工具扫描项目 A 的 .claude 文件夹。

        识别出安装了哪些 Agents, Skills 等。

        让用户在 UI 上勾选/剔除。

        保存为 scenes.json 中的一个条目。

    应用: 遍历场景内的列表，依次调用 逻辑 B (注入器)。

2. 页面一：设置页 (Settings) - [地基]

这是系统启动的第一步，必须确保配置正确。

标题: 全局配置 / Global Configuration

表单区域:

    本地武器库路径 (Library Path) [必填]

        UI组件: 输入框 (只读) + [选择文件夹] 按钮。

        逻辑: 调用 Electron dialog.showOpenDialog 选择目录。

        验证: 必须是可读写的目录。

        说明文本: "存放所有下载插件和标准化能力的根目录。"

    外部编辑器路径 (Editor Path) [必填]

        UI组件: 输入框 (只读) + [选择程序] 按钮。

        逻辑: 选择 .exe (Win) 或 .app (Mac) 或命令脚本。

        默认值: 尝试自动检测 code (VS Code)。

        说明文本: "点击文件时调用此程序打开 (例如 .md, .py)。"

    Git 可执行文件路径 [选填]

        UI组件: 输入框。

        默认值: git (依赖系统环境变量)。

    保存按钮:

        交互: 点击后写入 AppData/config.json，并弹出 "配置已保存" Toast。

7. 开发路线图建议 (给开发的指令)

你可以按照这个顺序发给 AI：

    Phase 1: 基础建设

        初始化 Electron + React + TypeScript。

        实现 Settings 页面，完成 config.json 的读写。

        实现 "左侧导航 + 页面路由" 框架。

    Phase 2: 市场/库逻辑

        完成 Git Clone 后端逻辑。

        完成 解析器 (Parser)：把下载的文件夹变成 metadata.json + assets 结构。

        实现 Library 页面展示。

    Phase 3: 项目管理逻辑

        实现 Projects 页面。

        实现 扫描与发现 (.claude 文件夹检测)。

        实现 角色切换 (Profile Switcher) 的文件复制逻辑。

    Phase 4: 注入逻辑 (核心难点)

        实现 Project Detail 的双栏 UI。

        实现 "冲突弹窗"。

        实现 Copy & Merge 的底层文件操作。
