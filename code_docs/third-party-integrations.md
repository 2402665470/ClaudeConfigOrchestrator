配置概览
-----------------------------------------------------------------------------------------------------------

Claude Code 支持灵活的配置选项，允许您组合不同的提供商和基础设施：

理解以下区别：
*   **企业代理**：用于路由流量的 HTTP/HTTPS 代理（通过 `HTTPS_PROXY` 或 `HTTP_PROXY` 设置）
*   **LLM 网关**：处理身份验证并提供提供商兼容端点的服务（通过 `ANTHROPIC_BASE_URL`、`ANTHROPIC_BEDROCK_BASE_URL` 或 `ANTHROPIC_VERTEX_BASE_URL` 设置）

两种配置可以同时使用。

### [​](https://code.claude.com/docs/zh-CN/third-party-integrations#%E5%B0%86-bedrock-%E4%B8%8E%E4%BC%81%E4%B8%9A%E4%BB%A3%E7%90%86%E7%BB%93%E5%90%88%E4%BD%BF%E7%94%A8)

将 Bedrock 与企业代理结合使用

通过企业 HTTP/HTTPS 代理路由 Bedrock 流量：

复制

询问AI

```
# 启用 Bedrock
export CLAUDE_CODE_USE_BEDROCK=1
export AWS_REGION=us-east-1

# 配置企业代理
export HTTPS_PROXY='https://proxy.example.com:8080'
```

### [​](https://code.claude.com/docs/zh-CN/third-party-integrations#%E5%B0%86-bedrock-%E4%B8%8E-llm-%E7%BD%91%E5%85%B3%E7%BB%93%E5%90%88%E4%BD%BF%E7%94%A8)

将 Bedrock 与 LLM 网关结合使用

使用提供 Bedrock 兼容端点的网关服务：

复制

询问AI

```
# 启用 Bedrock
export CLAUDE_CODE_USE_BEDROCK=1

# 配置 LLM 网关
export ANTHROPIC_BEDROCK_BASE_URL='https://your-llm-gateway.com/bedrock'
export CLAUDE_CODE_SKIP_BEDROCK_AUTH=1  # 如果网关处理 AWS 身份验证
```

### [​](https://code.claude.com/docs/zh-CN/third-party-integrations#%E5%B0%86-vertex-ai-%E4%B8%8E%E4%BC%81%E4%B8%9A%E4%BB%A3%E7%90%86%E7%BB%93%E5%90%88%E4%BD%BF%E7%94%A8)

将 Vertex AI 与企业代理结合使用

通过企业 HTTP/HTTPS 代理路由 Vertex AI 流量：

复制

询问AI

```
# 启用 Vertex
export CLAUDE_CODE_USE_VERTEX=1
export CLOUD_ML_REGION=us-east5
export ANTHROPIC_VERTEX_PROJECT_ID=your-project-id

# 配置企业代理
export HTTPS_PROXY='https://proxy.example.com:8080'
```

### [​](https://code.claude.com/docs/zh-CN/third-party-integrations#%E5%B0%86-vertex-ai-%E4%B8%8E-llm-%E7%BD%91%E5%85%B3%E7%BB%93%E5%90%88%E4%BD%BF%E7%94%A8)

将 Vertex AI 与 LLM 网关结合使用

将 Google Vertex AI 模型与 LLM 网关结合，实现集中式管理：

复制

询问AI

```
# 启用 Vertex
export CLAUDE_CODE_USE_VERTEX=1

# 配置 LLM 网关
export ANTHROPIC_VERTEX_BASE_URL='https://your-llm-gateway.com/vertex'
export CLAUDE_CODE_SKIP_VERTEX_AUTH=1  # 如果网关处理 GCP 身份验证
```

### [​](https://code.claude.com/docs/zh-CN/third-party-integrations#%E8%BA%AB%E4%BB%BD%E9%AA%8C%E8%AF%81%E9%85%8D%E7%BD%AE)

身份验证配置

Claude Code 在需要时使用 `ANTHROPIC_AUTH_TOKEN` 作为 `Authorization` 标头。`SKIP_AUTH` 标志（`CLAUDE_CODE_SKIP_BEDROCK_AUTH`、`CLAUDE_CODE_SKIP_VERTEX_AUTH`）用于 LLM 网关场景，其中网关处理提供商身份验证。
[​](https://code.claude.com/docs/zh-CN/third-party-integrations#%E9%80%89%E6%8B%A9%E6%AD%A3%E7%A1%AE%E7%9A%84%E9%83%A8%E7%BD%B2%E9%85%8D%E7%BD%AE)

选择正确的部署配置
-------------------------------------------------------------------------------------------------------------------------------------------------------------

选择部署方法时，请考虑以下因素：
### [​](https://code.claude.com/docs/zh-CN/third-party-integrations#%E7%9B%B4%E6%8E%A5%E6%8F%90%E4%BE%9B%E5%95%86%E8%AE%BF%E9%97%AE)

直接提供商访问

最适合以下组织：
*   希望最简单的设置
*   拥有现有的 AWS 或 GCP 基础设施
*   需要提供商原生监控和合规性

### [​](https://code.claude.com/docs/zh-CN/third-party-integrations#%E4%BC%81%E4%B8%9A%E4%BB%A3%E7%90%86)

企业代理

最适合以下组织：
*   拥有现有的企业代理要求
*   需要流量监控和合规性
*   必须通过特定网络路径路由所有流量

### [​](https://code.claude.com/docs/zh-CN/third-party-integrations#llm-%E7%BD%91%E5%85%B3)

LLM 网关

最适合以下组织：
*   需要跨团队的使用情况跟踪
*   希望在模型之间动态切换
*   需要自定义速率限制或预算
*   需要集中式身份验证管理

[​](https://code.claude.com/docs/zh-CN/third-party-integrations#%E8%B0%83%E8%AF%95)

调试
---------------------------------------------------------------------------------------

调试部署时：
*   使用 `claude /status`[斜杠命令](https://code.claude.com/docs/zh-CN/slash-commands)。此命令提供对任何应用的身份验证、代理和 URL 设置的可观测性。
*   设置环境变量 `export ANTHROPIC_LOG=debug` 以记录请求。

[​](https://code.claude.com/docs/zh-CN/third-party-integrations#%E7%BB%84%E7%BB%87%E7%9A%84%E6%9C%80%E4%BD%B3%E5%AE%9E%E8%B7%B5)

组织的最佳实践
-----------------------------------------------------------------------------------------------------------------------------------------

### [​](https://code.claude.com/docs/zh-CN/third-party-integrations#1-%E6%8A%95%E8%B5%84%E6%96%87%E6%A1%A3%E5%92%8C%E8%AE%B0%E5%BF%86)

1. 投资文档和记忆

我们强烈建议投资文档，以便 Claude Code 理解您的代码库。组织可以在多个级别部署 CLAUDE.md 文件：
*   **组织范围**：部署到系统目录，如 `/Library/Application Support/ClaudeCode/CLAUDE.md`（macOS），用于公司范围的标准
*   **存储库级别**：在存储库根目录中创建 `CLAUDE.md` 文件，包含项目架构、构建命令和贡献指南。将这些文件检入源代码控制，以便所有用户受益[了解更多](https://code.claude.com/docs/zh-CN/memory)。

### [​](https://code.claude.com/docs/zh-CN/third-party-integrations#2-%E7%AE%80%E5%8C%96%E9%83%A8%E7%BD%B2)

2. 简化部署

如果您有自定义开发环境，我们发现创建一种”一键式”安装 Claude Code 的方式是促进组织内采用的关键。
### [​](https://code.claude.com/docs/zh-CN/third-party-integrations#3-%E4%BB%8E%E6%8C%87%E5%AF%BC%E4%BD%BF%E7%94%A8%E5%BC%80%E5%A7%8B)

3.从指导使用开始

鼓励新用户尝试 Claude Code 进行代码库问答，或在较小的错误修复或功能请求上使用。要求 Claude Code 制定计划。检查 Claude 的建议，如果偏离轨道，请提供反馈。随着时间的推移，当用户更好地理解这种新范式时，他们将更有效地让 Claude Code 更自主地运行。
### [​](https://code.claude.com/docs/zh-CN/third-party-integrations#4-%E9%85%8D%E7%BD%AE%E5%AE%89%E5%85%A8%E7%AD%96%E7%95%A5)

4. 配置安全策略

安全团队可以配置托管权限，以确定 Claude Code 允许和不允许做什么，这不能被本地配置覆盖。[了解更多](https://code.claude.com/docs/zh-CN/security)。
### [​](https://code.claude.com/docs/zh-CN/third-party-integrations#5-%E5%88%A9%E7%94%A8-mcp-%E8%BF%9B%E8%A1%8C%E9%9B%86%E6%88%90)

5. 利用 MCP 进行集成

MCP 是为 Claude Code 提供更多信息的好方法，例如连接到票证管理系统或错误日志。我们建议一个中央团队配置 MCP 服务器，并将 `.mcp.json` 配置检入代码库，以便所有用户受益。[了解更多](https://code.claude.com/docs/zh-CN/mcp)。在 Anthropic，我们信任 Claude Code 为每个 Anthropic 代码库的开发提供支持。我们希望您像我们一样享受使用 Claude Code！
[​](https://code.claude.com/docs/zh-CN/third-party-integrations#%E5%90%8E%E7%BB%AD%E6%AD%A5%E9%AA%A4)
