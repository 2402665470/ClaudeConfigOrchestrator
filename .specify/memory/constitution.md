# Claude配置分发器项目宪法

## 核心原则

### I. 用户体验优先
- 所有功能设计必须以用户需求为中心
- 界面简洁直观，操作流程清晰
- 错误提示友好明确，提供解决方案
- 性能优先：启动快、响应快、资源占用少

### II. 安全性第一
- 配置文件敏感信息必须加密存储
- 支持权限验证和访问控制
- 审计日志记录所有关键操作
- 遵循最小权限原则

### III. 模块化架构
- 每个功能模块独立封装，职责单一
- 清晰的API接口定义
- 松耦合设计，便于扩展和维护
- 依赖注入，支持配置化

### IV. 测试驱动开发（TDD）
- 所有新功能必须先编写测试
- 单元测试覆盖率不低于85%
- 集成测试覆盖关键业务流程
- 测试用例包含边界情况和异常处理

### V. 配置即代码
- 所有配置项版本化管理
- 支持配置模板和继承
- 配置变更可追溯、可回滚
- 环境隔离（开发/测试/生产）

## 技术标准

### 前端技术栈
- React 18+ 作为UI框架
- TypeScript 提供类型安全
- Tailwind CSS 快速样式开发
- Electron 构建桌面应用

### 后端服务（如果需要）
- Node.js + Express/Fastify
- 数据库：SQLite（本地）/ PostgreSQL（远程）
- ORM：Prisma 或 TypeORM

### 开发规范
- ESLint + Prettier 代码格式化
- Husky + lint-staged 提交前检查
- Conventional Commits 提交信息规范
- 语义化版本控制

## 质量标准

### 性能要求
- 应用启动时间 < 3秒
- 配置文件加载时间 < 1秒
- UI响应时间 < 200ms
- 内存占用 < 200MB

### 可用性要求
- 支持Windows 10/11
- 支持macOS 12+
- 支持Linux主流发行版
- 提供详细的用户文档

### 可维护性
- 代码注释覆盖率 > 60%
- API文档完整准确
- 定期重构，技术债务管理
- 知识库建设和维护

## 决策框架

当面临技术选择时，按以下优先级决策：

1. **安全性**：是否影响系统安全？
2. **用户体验**：是否影响用户使用？
3. **性能**：是否影响系统性能？
4. **可维护性**：是否增加维护成本？
5. **开发效率**：是否提升开发速度？

## 治理

- 本宪法是项目最高指导原则，凌驾于所有其他实践
- 任何修改需要团队讨论、文档记录、迁移计划
- 所有PR审查必须验证是否符合宪法
- 定期（每季度）回顾和更新宪法
